## 1. 🏗️ Обзор архитектуры безопасности

TouchPass построен на многоуровневой эшелонированной модели безопасности (defense-in-depth), объединяющей физическую биометрию, криптографическую связь по последовательному порту, системные хранилища паролей ОС и песочницу браузера:

1. **Аппаратная биометрия (Сравнение отпечатков на чипе)**: Регистрация отпечатков пальцев, извлечение признаков, хранение шаблонов и биометрическое сравнение 1:N выполняются полностью на чипе оптического сканера отпечатков ZW101, подключенного к микроконтроллеру ESP32-S3. Изображения отпечатков, контрольные точки и биометрические шаблоны никогда не передаются по USB, не записываются на диск ПК и не отправляются в облачные сервисы.
2. **Протокол авторизации HMAC-SHA256 и зашифрованная связь**: Взаимодействие между демоном на ПК и прошивкой ESP32-S3 по последовательному порту Serial UART / USB использует криптографический протокол "запрос-ответ". Запросы подписываются с помощью HMAC-SHA256 в сочетании с одноразовыми случайными числами (nonce) для предотвращения атак повторного воспроизведения (replay attacks), несанкционированного внедрения сообщений и подмены данных. Передаваемые данные могут дополнительно шифроваться по алгоритму AES-CTR.
3. **Интеграция с системным хранилищем паролей ОС**: Пароли, учетные данные `sudo` и ключи API никогда не сохраняются в открытом виде в коде, конфигурационных файлах или энергонезависимой памяти микроконтроллера. TouchPass извлекает учетные данные по запросу через библиотеку `keyring` напрямую из защищенных хранилищ ОС:
   - **Windows**: Диспетчер учетных данных Windows (через `win32crypt` / `keyring`)
   - **macOS**: Служба Keychain (через `keyring`)
   - **Linux**: API Secret Service / Freedesktop SecretService (через `keyring`)
   Пароли находятся в оперативной памяти ПК только в течение времени, необходимого для выполнения действия, и немедленно удаляются из памяти.
4. **Песочница WebUSB / WebSerial и веб-портала**: Браузерный прошивщик Web Flasher работает строго в рамках защищенной песочницы WebUSB/WebSerial современных браузеров. Локальный демон веб-портала TouchPass привязывается исключительно к локальному интерфейсу loopback (`127.0.0.1:8787`) и задействует строгие заголовки Cross-Origin Resource Sharing (CORS) для защиты от выполнения команд сторонними веб-сайтами.
5. **Исполнение нажатий USB HID клавиатуры**: Подтвержденные биометрические триггеры отправляют стандартные нажатия клавиш USB HID напрямую в текущее активное (сфокусированное) окно приложения. TouchPass не может нажимать графические кнопки GUI, взаимодействовать с фоновыми приложениями или обходить границы изоляции процессов ОС.

## 2. 🛡️ Модель угроз и матрица защиты

В таблице ниже подробно описана модель угроз TouchPass, выявленные векторы рисков и реализованные меры защиты:

| Вектор угрозы | Уровень риска | Механизм защиты |
| :--- | :--- | :--- |
| **Кража аппаратного ключа** | Средний | Устройство хранит только парный ключ HMAC. Выпуск нажатий клавиш требует физического совпадения биометрии на датчике ZW101; кража только аппаратуры не дает доступа к паролям. |
| **Перехват данных USB / Serial** | Средний | Связь по последовательному порту использует подписи HMAC-SHA256 с одноразовыми nonce; опциональное шифрование AES-CTR предотвращает пассивный перехват данных. |
| **Атаки повторного воспроизведения** | Средний | Одноразовые временные метки и nonce гарантируют, что перехваченные пакеты последовательного порта не могут быть повторно отправлены вредоносным ПО. |
| **Вредоносное ПО на ПК / Чтение памяти** | Высокий | Учетные данные хранятся в защищенном хранилище ОС (Keychain / Credential Manager), загружаются в память только при аппаратном подтверждении и стираются сразу после ввода. |
| **Удаленная эксплуатация веб-портала** | Высокий | Локальный сервер строго привязан к `127.0.0.1`; запросы API требуют строгой проверки CORS и локальной сессии. |
| **Спуфинг биометрического датчика** | Низкий-Средний | Оптический биометрический сканер ZW101 обеспечивает сравнение с коэффициентом ложного совпадения (FAR) < 0.001% и локальной проверкой на чипе. |

## 3. 📋 Поддерживаемые версии

Обновления безопасности и исправления уязвимостей активно поддерживаются для следующих релизов:

| Версия | Поддерживается | Статус и примечания |
| :--- | :--- | :--- |
| `2.0.x` | ✅ Да | Текущий активный релиз (Многоязычный веб-портал, Web Flasher и USB HID). |
| `< 2.0.0` | ❌ Нет | Устаревшие предварительные версии; исправления безопасности не переносятся на старые версии. |

## 4. 🚨 Сообщение об уязвимостях

Мы серьезно относимся к безопасности TouchPass. Если вы обнаружите или заподозрите уязвимость в компонентах TouchPass (оборудование, прошивка или ПО), пожалуйста, сообщите об этом с соблюдением принципов ответственного разглашения:

1. **Не создавайте публичные issues на GitHub** и не публикуйте детали нераскрытых уязвимостей на форумах.
2. Направьте подробный отчет разработчикам по электронной почте `security@touchpass.dev` или через **GitHub Private Vulnerability Reporting**.
3. Пожалуйста, включите в отчет следующие сведения:
   - Четкое описание уязвимости и потенциального воздействия на безопасность.
   - Пошаговую инструкцию по воспроизведению или код Proof of Concept (PoC).
   - Версию ПО, операционную систему и ревизию оборудования (ESP32-S3 / ZW101).

### Регламент ответа на уязвимости (SLA)
- **Подтверждение получения**: В течение **48 часов**.
- **Оценка и план исправления**: В течение **7 рабочих дней**.
- **Публичное раскрытие**: Осуществляется одновременно с выходом официального патча безопасности или после него.

## 5. 🔒 Лучшие практики безопасности для операторов

Для обеспечения максимальной безопасности при развертывании и использовании TouchPass:

- **Официальные источники прошивки**: Прошивайте устройство только сборками из официального репозитория или через проверенный [TouchPass Web Flasher](https://tody-agent.github.io/Touch-Pass/web/flasher/).
- **Физическая безопасность оборудования**: Относитесь к устройству TouchPass как к физическому ключу. Не оставляйте подключенный ключ без присмотра в ненадежной среде.
- **Безопасность парного ключа**: Храните в секрете парный ключ HMAC между ПК и устройством. В случае компрометации ПК выполните ротацию парного ключа и перерегистрируйте пароли в хранилище ОС.
- **Защита учетной записи ОС**: Используйте полнодисковое шифрование (BitLocker / FileVault) и короткий таймаут блокировки экрана на рабочей станции.
